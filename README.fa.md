# پیشکار

[English](README.md) · **فارسی**

**پیشکار** دستیار خودمیزبان و رایگانی است که کنار [Dokploy](https://dokploy.com) روی سرور
شما کار می‌کند؛ مثل پیشکاری که کارهای خانه را می‌گرداند. کارش این است که وقتی اینترنت
قطع یا کند می‌شود، build و deploy شما نخوابد: مخزن npm و PyPI خصوصی با جابه‌جایی خودکار بین
منبع‌ها، فضای ذخیره‌سازی S3، سرور DNS، پشتیبان‌گیری، پایش منابع، فایروال و ابزارهای Docker،
همه در یک پنل فارسی.

> این پروژه پیش‌تر با نام *MRK* ساخته شده است. نام ریپو، بسته‌ها، ایمیج و کانتینرها
> (`mrk-mirror`، `mrk-dns`، متغیرهای `MRK_*`، مسیر `/opt/mrk`) همان پیشوند را نگه می‌دارند؛
> فقط نام محصول عوض شده است.

- مجوز: [MIT](LICENSE). برای همه رایگان است و نسخه پولی ندارد.
- وضعیت: در حال توسعه (نسخه 0.1). پیش از باز کردن پنل روی اینترنت، [SECURITY.md](SECURITY.md) را بخوانید.

## امکانات

**مخزن پکیج**
- مخزن npm (با [Verdaccio](https://verdaccio.org) 6) و آینه PyPI (با [devpi](https://devpi.net)) روی سرور خودتان.
- چند منبع برای هر مخزن، با بررسی سلامت و جابه‌جایی خودکار؛ مثلاً اول npmjs.org و اگر جواب نداد آینه داخلی. timeout، خطای شبکه و خطای 5xx سراغ منبع بعدی می‌رود.
- پکیجی که یک بار دریافت شده، حتی با قطع کامل اینترنت نصب می‌شود.
- سیاست پکیج و قرنطینه، بررسی سلامت فایل‌ها، پاک‌سازی با سطل بازیافت و منبع‌های npm خصوصی.
- با `npm`، `pnpm`، `yarn`، `pip`، `uv` و `poetry` کار می‌کند.

**سرویس‌های بومی** (برای همین پروژه نوشته شده‌اند، نه سرور آماده دیگران)
- **فضای ذخیره‌سازی سازگار با S3**: امضای SigV4 و لینک موقت، آپلود چندتکه، باکت‌های مدیریت‌شده و *پوشه‌های متصل* (یک پوشه روی سرور که به‌شکل باکت دیده می‌شود)، برچسب، قانون چرخه عمر، نسخه‌بندی و مدیریت فایل در پنل. می‌توانید آن را مقصد پشتیبان Dokploy کنید.
- **سرور DNS** (به زبان Go): زون‌های اختصاصی، بازنویسی نام، ارسال به DNS دیگر یا جست‌وجوی کامل از ریشه با اعتبارسنجی DNSSEC، اتصال رمزنگاری‌شده DoT/DoH/DoQ، لاگ فشرده پرسش‌ها، آمار، و تشخیص حمله با اقدام خودکار و برگشت‌پذیر. هیچ‌وقت DNS باز برای همه اینترنت نمی‌شود.

**مدیریت سرور کنار Dokploy**
- اتصال به Dokploy از راه API رسمی خودش؛ دامنه دادن به هر سرویس از طریق Dokploy بدون دست زدن به پورت‌های 80 و 443.
- Host Agent اختیاری: کانتینرها، لاگ زنده، روشن و خاموش و ری‌استارت، دریافت ایمیج و پاک‌سازی امن با پیش‌نمایش (کانتینرهای خود Dokploy محافظت می‌شوند).
- پایش منابع، پیگیری آپدیت ایمیج‌ها، اسکن آسیب‌پذیری (OSV) و خروجی SBOM با قالب CycloneDX و SPDX.
- مدیریت دیتابیس PostgreSQL، MySQL/MariaDB، MongoDB و Redis (پیش‌فرض فقط‌خواندنی).
- دستیار فایروال اختیاری با nftables: تشخیص حمله حدس رمز از لاگ sshd، Traefik و پنل؛ پیش‌فرض فقط گزارش می‌دهد و هر مسدودسازی خودش منقضی می‌شود.

**نگهداری**
- پشتیبان رمزنگاری‌شده (AES-256-GCM و scrypt) با بازگردانی آفلاین و قابل برگشت.
- پشتیبان سرور و دیتابیس‌ها در پوشه، هر سرویس S3 یا S3 خود پیشکار، با زمان‌بندی و آزمایش بازگردانی.
- اعلان با تلگرام، بله، ایمیل و webhook امضاشده، با قانون و ساعت سکوت.
- کاربرها، نقش‌های آماده و دلخواه، دعوت‌نامه، نشست‌ها و تاریخچه کارها با خروجی CSV.
- پروکسی خروجی (HTTP و SOCKS5) جدا برای هر سرویس.
- همه تنظیم‌ها در **تنظیمات ← همه تنظیمات** با توضیح، پیش‌فرض و جای تنظیمشان فهرست شده‌اند.
- رابط فارسی (راست‌به‌چپ) و انگلیسی، با حالت *ساده* و *پیشرفته* در همه صفحه‌ها.

## نصب سریع (Docker)

پیش‌نیاز: یک سرور لینوکس (amd64 یا arm64) با Docker Engine و افزونه Compose (روی سرورهای
Dokploy هر دو هست)، 2 گیگابایت رم آزاد و فضای دیسک برای کش پکیج‌ها.

<div dir="ltr">

```bash
git clone https://github.com/SeniorKian/MrK_DevAssist.git pishkar && cd pishkar && docker compose up -d --build
```

</div>

این فرمان ایمیج را از سورس می‌سازد و پنل، npm، PyPI و S3 را بالا می‌آورد. همه پورت‌ها فقط روی
`127.0.0.1` باز می‌شوند. از کامپیوتر خودتان یک تونل SSH بزنید و <http://localhost:8080> را باز کنید:

<div dir="ltr">

```bash
ssh -L 8080:127.0.0.1:8080 you@your-server
```

</div>

بار اول صفحه **راه‌اندازی اولیه** باز می‌شود؛ همان لحظه حساب مالک را بسازید.
برای استفاده واقعی (ایمیج منتشرشده، دامنه، TLS از طریق Dokploy، DNS و فایروال و Agent و
راهنمای پورت 53) **[docs/install-docker.fa.md](docs/install-docker.fa.md)** را بخوانید.

## نصب بدون Docker

پیشکار روی Debian 12/13 و Ubuntu 22.04/24.04 مستقیم و به‌شکل سرویس systemd هم اجرا می‌شود؛
با همان برنامه‌ها، همان نسخه‌ها و همان محدودیت‌های امنیتی کانتینر:

<div dir="ltr">

```bash
git clone https://github.com/SeniorKian/MrK_DevAssist.git pishkar && cd pishkar
sudo bash scripts/install-native.sh install --dry-run   # first, see the plan
sudo bash scripts/install-native.sh install            # optional: --with-dns --with-firewall --with-agent
```

</div>

پیش از شروع **[docs/install-native.fa.md](docs/install-native.fa.md)** را بخوانید.

## تنظیمات در یک نگاه

- تنظیم‌ها سه لایه دارند: **پنل** (بیشتر تنظیم‌ها، بدون ری‌استارت)، **متغیرهای محیطی** `MRK_*`
  (هنگام شروع خوانده می‌شوند) و **آرگومان‌های build** (آینه دانلود هنگام ساخت ایمیج). متغیر
  محیطی صریح همیشه برنده است.
- در پنل، **تنظیمات ← همه تنظیمات** همه موارد را با توضیح، پیش‌فرض، منبع فعلی و نیاز به
  ری‌استارت نشان می‌دهد. منبع اصلی، رجیستری تنظیمات در
  `apps/control-plane/src/mrk_control_plane/settings_registry_entries_*.py` است.
- Docker: مقدارهایی که Compose می‌خواند در [`.env.example`](.env.example) است (آن را به `.env`
  کپی کنید)؛ تنظیمات کانتینر در `compose.yaml` و `deploy/appliance/compose.production.yaml`.
- بدون Docker: فایل `/etc/pishkar/pishkar.env` (نمونه: [`deploy/native/pishkar.env.example`](deploy/native/pishkar.env.example)).
- پیش از عمومی کردن، دست‌کم `MRK_TRUSTED_HOSTS`، `MRK_CORS_ORIGINS` و `MRK_PYPI_OUTSIDE_URL`
  (یا دامنه‌ها در پنل) را روی نام‌های HTTPS واقعی بگذارید.
- دیتابیس پیش‌فرض PGlite داخلی است؛ برای نصب بزرگ‌تر `MRK_DATABASE_URL` را به یک PostgreSQL
  بیرونی (`postgresql+psycopg://...`) بدهید. بیشتر: [docs/27](docs/27-configurability-and-settings.md).

## نکته‌های امنیتی

- **پنل را زود صاحب شوید.** تا حساب مالک ساخته نشده، هر کس زودتر به پنل برسد می‌تواند آن را
  بسازد. تا پایان راه‌اندازی اولیه پنل را روی `127.0.0.1` (پیش‌فرض) نگه دارید.
- پیش از استفاده از راه اینترنت، پنل را پشت TLS ببرید (Dokploy/Traefik یا هر reverse proxy دیگر)
  و `MRK_TRUSTED_PROXIES` را تنظیم کنید تا تاریخچه کارها نشانی واقعی کاربران را ببیند.
- کانتینر اصلی با کاربر `10001`، بدون هیچ capability، با فایل‌سیستم فقط‌خواندنی و
  `no-new-privileges` اجرا می‌شود. سرویس‌های systemd نصب بدون Docker همین قواعد را دارند.
- **Host Agent** اختیاری به سوکت Docker دسترسی دارد و این یعنی دسترسی root به سرور. فقط
  درخواست‌های فهرست مجاز داخل کد را می‌فرستد و فقط به درخواست امضاشده با HMAC جواب می‌دهد.
- **دستیار فایروال** اختیاری با root ولی فقط با `CAP_NET_ADMIN` اجرا می‌شود و فقط به جدول
  nftables خودش (`inet mrk`) دست می‌زند. در شروع فقط گزارش می‌دهد.
- عبارت عبور پشتیبان و فایل `MRK_UPSTREAM_SECRET_KEY_FILE` را بیرون از پوشه داده نگه دارید.
- آسیب‌پذیری‌ها را خصوصی گزارش کنید؛ [SECURITY.md](SECURITY.md) را ببینید.
