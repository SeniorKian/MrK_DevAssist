# 47 — نسخه‌ها و به‌روزرسانی

## یک نسخه برای همه چیز

فایل `VERSION` در ریشه مخزن تنها منبع نسخه است (مثلاً `0.1.0`، به قالب SemVer). همه ایمیج‌ها با همین
نسخه منتشر می‌شوند و پنل نسخه خودش را می‌شناسد (`MRK_IMAGE_TAG`)، پس ویزارد همیشه ایمیج سرویس‌ها را با
**همان نسخه پنل** می‌دهد؛ هیچ Stackی به `latest` تکیه نمی‌کند.

| ایمیج | برچسب‌ها |
|---|---|
| `ghcr.io/<owner>/mrk-panel` و `mrk-agent`، `mrk-firewall`، `mrk-dns`، `mrk-s3`، `mrk-npm`، `mrk-pypi` | `X.Y.Z`، `X.Y`، `latest` |
| Git ‏(Gitea) و مخزن ایمیج ‏(Zot) | ایمیج رسمی با digest ثابت؛ با هر نسخه پنل که قالبشان عوض شود به‌روز می‌شوند |

## انتشار نسخه تازه

<div dir="ltr">

```bash
python scripts/release.py 0.2.0 --push
```

</div>

این فرمان نسخه را در `VERSION`، `pyproject.toml`، `__init__.py`، `package.json`/`package-lock.json` و برچسب
پیش‌فرض ایمیج پنل در `compose.yaml` می‌نویسد، بخش `[Unreleased]` در `CHANGELOG.md` را به `[0.2.0] - تاریخ`
تبدیل می‌کند، commit و برچسب `v0.2.0` می‌سازد و push می‌کند. بعد GitHub Actions:

1. همه تست‌ها و بررسی‌ها را دوباره اجرا می‌کند و اگر برچسب با `VERSION` یکی نباشد متوقف می‌شود؛
2. هر ایمیج را می‌سازد، با Trivy اسکن می‌کند، SBOM و provenance می‌گذارد و با سه برچسب بالا منتشر می‌کند؛
3. یک GitHub Release با یادداشت‌های همان نسخه از `CHANGELOG.md` می‌سازد.

`python scripts/release.py --check` فقط بررسی می‌کند که همه فایل‌ها با `VERSION` یکی باشند (CI هم همین را
روی هر push اجرا می‌کند).

## به‌روزرسانی از پنل

صفحه «سرویس‌های من ← نسخه‌ها و به‌روزرسانی»:

- پنل هر ۱۲ ساعت (و با دکمه «بررسی دوباره») آخرین نسخه پایدار را از رجیستری ایمیج‌ها می‌خواند و اگر نسخه
  تازه‌ای آمده باشد خبر می‌دهد (با پیوند یادداشت‌های انتشار و اعلان).
- **اول پنل:** اگر پنل در Dokploy نصب شده باشد، با یک دکمه (و تأیید تایپی «UPDATE») ایمیج پنل در همان Stack
  عوض و دوباره deploy می‌شود. در غیر این صورت دستور دقیق نشان داده می‌شود:
  `MRK_PANEL_IMAGE` یا `git pull` و بعد `docker compose pull && docker compose up -d`؛ نصب بومی:
  `git checkout vX.Y.Z && sudo bash scripts/install-native.sh upgrade`.
- **بعد سرویس‌ها:** هر سرویس نسخه فعلی و نسخه هم‌خوان با پنل را نشان می‌دهد. سرویسی که پنل خودش با Dokploy یا
  Coolify نصب کرده با یک دکمه به‌روز می‌شود: پنل env فعلی را از همان‌جا می‌خواند، **فقط خط `MRK_IMAGE`** را
  عوض می‌کند (کلیدهای اتصال و بقیه مقدارها دست نمی‌خورند)، قالب Compose همین نسخه را می‌گذارد، deploy می‌کند و
  دوباره وصل می‌شود. برای نصب دستی، فایل compose تازه، همان یک خط env و قدم‌ها نشان داده می‌شود.
